# 기술 설계와 ADR

## ADR-001: GitHub Markdown을 단일 원본으로 유지

이미 합의된 작성·검토 이력과 자동화가 GitHub에 있으므로 DB를 추가하지 않는다. 웹은 공개 저장소를 빌드 시 읽어 정적 결과를 만든다. 이 결정은 동기화와 별도 권한 관리 비용을 없앤다.

## ADR-002: 외부 입력은 런타임 검증

TypeScript 타입만 신뢰하지 않고 Zod와 도메인 검사를 함께 적용한다. 원본 오류는 이전 정상 배포를 유지할 수 있도록 새 빌드를 실패시킨다.

## ADR-003: 재배포 경계

아카이브 저장소가 웹 저장소에 `archive-updated` dispatch를 보내고, 웹 저장소가 호스팅 deploy hook을 호출한다. 장애 시 GitHub Actions 로그에서 실패 단계를 확인하고, 원본을 수정한 뒤 수동 dispatch로 복구한다.

## 바이브코딩 작업 계약

- 한 번에 하나의 사용자 결과와 인수 조건만 구현한다.
- DB, 인증, 전역 상태, UI 프레임워크를 임의로 추가하지 않는다.
- 관련 문서와 테스트를 코드 변경과 같은 작업 안에서 갱신한다.
- lint, typecheck, 관련 테스트와 브라우저 확인을 통과한 단위만 완료한다.

## Definition of Done

요구사항 추적 가능, 접근 가능한 상호작용, 실패 상태 처리, 자동 검사 통과, 모바일·데스크톱 확인, 운영 문서 반영을 모두 만족한다.
