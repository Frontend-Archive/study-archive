# 정보 구조 및 디자인

## 정보 구조

- `/`: 제품 소개, 누적 현황, 검색·필터, 회차 타임라인, 주제 목록, 멤버 소개
- `/sessions/[id]`: 한 회차의 날짜·진행 방식·발표 슬롯
- `/members/[slug]`: 한 멤버의 활동 요약, 주제 분포와 오래된 순 학습 기록
- `/topics/[slug]`: 웹에서 분류한 한 주제의 최신순 학습 기록
- `/feed.xml`: 게시된 글의 최신순 RSS 피드
- `/about`: 문제의식, 운영 방식, 데이터 원본

검색 상태는 `q`, `author`, `tag`, `topic` 쿼리로 표현한다. 검색 패널은 여섯 개의 주제 분류를 제공하고, 세부 태그는 각 글에서 직접 선택한다.

회차·주제·멤버는 같은 위계의 탐색 축이다. 셋 모두 홈의 독립 섹션으로 두고 헤더 메뉴에서 같은 방식으로 연결한다. 각 섹션의 항목은 해당 상세 페이지로 이동한다.

## 링크 동작 규칙

같은 화면에 동작이 다른 링크를 섞지 않는다. 동작은 기호로 구분한다.

- `↗`: 새 탭에서 외부 원문을 연다. 글 제목과 GitHub 링크가 해당한다.
- `→`: 사이트 안의 다른 페이지로 이동한다. 주제·멤버·회차 목록의 항목이 해당한다.
- `←`: 상위 목록으로 돌아간다.
- `#태그`: 페이지를 옮기지 않고 홈 아카이브의 필터를 적용한다.

글 한 줄에서 이동할 수 있는 곳은 원문, 작성자 또는 회차, 태그 세 가지뿐이다. 태그와 주제처럼 생김새가 비슷하면서 동작이 다른 요소를 나란히 두지 않는다. 페이지 안에서 스크롤만 하는 버튼은 두지 않는다.

## 페이지 상단

모든 페이지의 상단은 `PageHero` 하나로 통일한다. 구성은 위에서 아래로 네 층이다.

1. 뒤로가기 링크와 영문 분류 라벨을 같은 줄에 둔다.
2. 페이지 제목. 화면에서 가장 큰 활자이며 페이지당 하나의 `h1`이다.
3. 설명 한 문단.
4. 날짜·개수·기간 같은 메타 정보 한 줄.

- 제목·설명·메타는 모두 왼쪽 한 기둥에 정렬한다. 설명을 오른쪽으로 밀어 따로 띄우지 않는다.
- 섹션 제목(`h2`)은 어떤 폭에서도 페이지 제목보다 작게 유지해, 방문자가 현재 페이지를 먼저 인식하도록 한다.
- 상단 영역은 첫 화면을 가리지 않는 높이를 유지한다. 데스크톱 1280px에서 본문 첫 항목까지 약 350px, 모바일 360px에서 약 350px가 기준이다.
- 가로 구분선은 한 경계에 하나만 둔다. 상단 영역 바로 아래에 섹션 라벨의 구분선이 오는 페이지에서는 상단 영역의 선을 생략한다.
- 제목이 이미 담고 있는 정보를 장식으로 반복하지 않는다.

## 멤버 페이지

- 히어로에서 전체 회차 대비 게시 기록 수와 최초·최근 활동 기간을 소개한다.
- 게시 기록, 최근 관심사, 활동 기간은 상단 영역의 메타 줄에 한 줄로 요약하고, 아카이브 태그로부터 주제 흔적을 자동으로 엮는다.
- 자유 태그의 작성 방식이 멤버 비교처럼 보이지 않도록 주제 수·순위·기록 수는 표시하지 않는다.
- 주제 흔적은 최근 기록에 등장한 순서와 동일한 크기로 보여주며, 선택 시 작성자와 주제가 함께 적용된 홈 아카이브로 이동한다.
- 학습 로그에는 게시 여부와 관계없이 모든 회차 슬롯을 오래된 순으로 노출한다.
- 페이지 끝의 이전·다음 탐색으로 네 멤버의 서로 다른 관점을 이어서 살펴볼 수 있다.

## 디자인 원칙

- 따뜻한 종이색, 짙은 잉크색, 단일 코발트 블루로 에디토리얼 인상을 만든다.
- 페이지명을 직접 드러내는 절제된 제목으로 위계를 만든다. 여백은 위계를 만드는 만큼만 쓰고, 본문을 첫 화면 밖으로 밀어내지 않는다.
- 본문과 제어 요소는 산세리프를 사용하고, 제목에서는 영문을 중립적인 산세리프, 한글을 세리프 계열로 조합한다.
- 모션은 의미 있는 호버와 진입에만 쓰고 reduced motion 환경에서는 제거한다.
- 색만으로 상태를 구분하지 않고 텍스트 레이블을 함께 제공한다.
